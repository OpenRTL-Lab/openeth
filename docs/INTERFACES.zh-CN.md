# 架构与接口

[English](INTERFACES.md)

OpenNIC 是 OpenETH 靠近主存的控制器：软件通过控制／状态寄存器（CSR）提交
缓冲描述符，直接内存访问（DMA）引擎搬运报文。TX 指 FPGA 向对端发送，RX 指
FPGA 从对端接收。发送路径为 OpenNIC→整帧缓存／跨时钟域（CDC）／64转8→MAC
→RGMII→外部 PHY，接收反向。DMA 访问的是 **SoC 主存** 与帧存储，不是对端
计算机的内存；驱动仍需在报文与 DMA 缓冲之间拷贝，不等于 Linux 零拷贝。
参考 CPU50MHz 与线侧125MHz必须区分。

NIC原生请求/响应和DMA为valid/ready握手，两者同时为高才传输；valid高而ready低时
发送方保持字段不变。FrameBeat 是本项目的报文流记录：64位data、8位有效字节
掩码keep、帧尾标记last和帧错误标记error。非尾keep必须0xff，尾keep须非零且
从最低字节连续有效，例如0x01/0x03/0xff，不能0x05。
描述符含按8字节对齐的64位内存地址、16位长度/cookie，发布最大2048字节；cookie是软件给定的
请求标识，完成时原样返回。完成项含长度、cookie
和状态。内存为64位读及带字节掩码写、显式完成/错误，桥接读写使用独立源标识。

下表为NIC相对偏移，参考基址0x10016000；PHY管理另在0x6000，不可混用。
移植前核对源码的字节写使能和非法访问错误。读取完成弹出寄存器会移除队头，读取计数不会。

| 偏移 | 含义 |
| --- | --- |
| 0x00 / 0x04 | ID为0x4f4e4943／ABI版本0x00010000 |
| 0x08 / 0x0c | 控制／使能与清空，忙状态 |
| 0x10 / 0x14 | 中断掩码／待处理状态；第0位 TX、第1位 RX |
| 0x20 / 0x24 / 0x28 / 0x2c | TX地址低／高、元数据、提交 |
| 0x30 / 0x34 / 0x38 / 0x3c | RX地址低／高、元数据、提交 |
| 0x40 / 0x44 | 破坏性TX完成弹出／计数 |
| 0x48 / 0x4c | 破坏性RX完成弹出／计数 |
| 0x50 | RX队头状态，须先读再弹出RX完成项 |
| 0x54 | 描述符队列剩余空间 |
| 0x58 / 0x5c | 丢弃／DMA错误计数 |

中断第0位表示发送、第1位表示接收，
由完成队列非空和掩码形成电平，**本版无可编程硬件中断聚合**。DMA 采用停等式主存事务，
不能假定突发或多个未完成事务并发的吞吐。驱动拥有一致性缓冲并拷贝skb，已有NAPI/GRO，
校验和在软件处理，不伪称硬件卸载。

整帧和元数据写完后才允许另一时钟域读取该槽。任一侧复位都会重置 FIFO 所有权指针，
使缓存中和传输中的帧失效，但不清空 RAM 字节；各侧通过本域同步释放链恢复，
不能把 RAM 残留内容当作新帧。
RX按策略丢弃坏帧/超长/缓冲满帧，支持内部背压不代表PHY可无限暂停。
实际集成须读[约束步骤](../buffer/constraints/openeth_frame_cdc.tcl)，独立核CDC、RAM、
复位及建立／保持／恢复时间，不能靠全域假例外掩盖问题。

RGMII发送的clk90相对clk移相90度，即125MHz下的2ns；接收使用PHY提供的时钟。
复位使内部帧失效，不代表输出引脚立即清零：停钟时双沿输出寄存器可保持末值，
直至下一时钟沿，不能把帧失效机制当作引脚异步复位保证。
三份FPGA I/O封装需要相应原语／支持的通用模型；PHY延时模式及板上走线、封装在
工艺、电压、温度（PVT）范围内的延时预算由实际系统负责，不因组件仿真通过自动满足。
